# api-test 用户故事（口语版）

## 小李是 QA，第一天上班

1. 打开 api-test，看到三个大按钮：「录流量」「导文档」「手写调试」
2. 点「录流量」→ 装了个 Chrome 插件 → 正常用业务系统
3. 回来一看，左边冒出了 18 个 API
4. 点「从录制生成用例」→ AI 列了 12 条候选
5. 勾了 8 条，点「入库」→ 8 条用例出现在列表
6. 点「全部运行」→ 7 过 1 挂
7. 点挂的那条 → 看到期望 vs 实际的红色 diff
8. 点「AI 诊断」→ AI 说「amount 字段类型变了」
9. 完成，5 分钟。

## 小李日常调试（每天几十次）

1. 左树点一个 API → 中间出现请求编辑器
2. 改参数 → 按 Enter → 响应出来了（JSON 有颜色）
3. 点「AI 生成断言」→ AI 帮我写了 3 条
4. 勾 2 条 → ⌘S 存用例
5. 下次回归自动跑，不用再管。

## 小王是后端，刚改完一段代码

1. 打开 api-test，搜自己的 API，点进去
2. 点「发送」→ 500 了
3. 点「AI 诊断」→ AI 告诉他哪行代码的问题
4. 改完再发一次 → 200 → 走人，前后 30 秒。

## 张姐是 PM，每周五看报告

1. 打开覆盖率页面，看到 67%
2. 看到红色标记的 POST /orders 没测
3. 问小李，小李点「✦ 补测」→ AI 生成边界用例 → 入库
4. 下周涨到 82%。

## 小李串场景（每周一次）

1. 新建场景「下单流程」
2. 把登录、创建订单、查列表三个 API 拖进来
3. 配置：登录的 token 传给后面的请求
4. 加个循环（跑 3 次）+ 加个条件（余额不够就跳过）
5. 点运行 → 绿的绿的红的黄的
6. 点红的看 diff → 存场景 → 加入回归。
